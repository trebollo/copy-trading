## Finances persist/load effect race

`FinancesPageContent` initializes with `useState<Transaction[]>(initialTransactions)` and has two effects:

```typescript
// Effect 1 (load)
useEffect(() => {
  setTransactions(loadTransactions());
}, []);

// Effect 2 (persist)
useEffect(() => {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(transactions));
}, [transactions]);
```

On mount, both effects fire after the first render. Effect 1 calls `setTransactions` with localStorage data, but Effect 2 writes `initialTransactions` (the current state at render time) to localStorage. The fix is to initialize state directly: `useState<Transaction[]>(loadTransactions)` (passing the function reference as lazy initializer) and removing the load effect. This avoids the two-render dance and the transient overwrite.

## Hardcoded tradesToday

```typescript
const totalPnl = groupDailyPnl.reduce((sum, d) => sum + d.pnl, 0);
const avgRiskMultiplier = members.reduce(...) / members.length;
const winRate = Math.round((winningDays / groupDailyPnl.length) * 100);
const tradesToday = 12; // ← still hardcoded
```

The first three respond to changes in their backing data. The fourth doesn't. Adding a `trades` field to `groupDailyPnl` entries (matching the `PnlCalendarData` shape) would allow `tradesToday` to be derived from the last entry.

# Broken actions, PnL calendar, finances page, and group stats

This change wires up every dead button in the copy-trading dashboard (sync, edit, connect, notifications, search), adds a PnL calendar heatmap component to the Metrics and Account Detail views, creates a new Finances page with full CRUD for expenses and payouts, and enriches the Groups section with daily PnL charts and expanded stats cards. All state is local/mock — no backend persistence beyond a localStorage fallback on settings save. The implementation spans 22 files, adding roughly 1,500 lines of new UI code.

**Watch for:** Platform "Reconnect" button toggles connection *off* instead of re-establishing it (confirmed). `useParams` imported but unused in Account Detail page — dead import that litters the bundle (confirmed). Group detail page hardcodes all stats (Total PnL, Trades Today, Win Rate) rather than deriving them from the mock members array, meaning those numbers will silently diverge when member data changes (confirmed).

## High-level view

The action-wiring pass (FEAT-001) systematically adds handlers to every previously-inert button: sync triggers update timestamps and toasts, edit opens inline dialogs, settings save falls back to localStorage when the API returns non-200. The one misstep is the platform connect/disconnect toggle — "Reconnect" on a connected platform flips the connection to "disconnected", which is the opposite of what the label promises.

The PnL calendar (FEAT-002) is a self-contained heatmap grid using date-fns for month arithmetic and CSS-only color intensity. It takes a `{date, pnl, trades}[]` prop and renders with month navigation and hover tooltips. It's reused in both the Metrics dashboard and the Account Detail page without type mismatches since `DailyMetricData` already matches `PnlCalendarData`.

The Finances page (FEAT-003) introduces a full transactional view: summary cards, type-filter select, a sortable transaction table with row-level edit/delete via dropdown, and a monthly breakdown table. All state lives in `useState` — there's no persistence across page reloads, unlike the settings page which demonstrates the localStorage fallback.

The Groups enhancement (FEAT-004) adds daily PnL indicators on group cards and a dedicated chart section with period breakdowns on the group detail page. The extended stats (Total PnL, Win Rate, Avg Risk Multiplier, Trades Today) are hardcoded scalars rather than computed from the mock members, so the numbers exist in two disconnected truth sources that already contradict each other.

<summary>Issues (5)</summary>

1. **Reconnect disconnects** — `handlePlatformToggle` in settings page toggles status from "connected" to "disconnected" when the user clicks "Reconnect". The button should cycle the connection (briefly disconnect then reconnect) or at minimum remain connected. Fix: don't flip status when already connected; set `lastSync: "Just now"` and toast "reconnected".
2. **Unused `useParams` import in Account Detail** — `useParams` and `params` are imported and called but the returned value is never consumed. Remove the import and the assignment, or use `params.id` to select account data.
3. **Group stats not derived from data** — Total PnL, Trades Today, Win Rate, and Avg Risk Multiplier on the group detail page are hardcoded numbers (`3245.50`, `12`, `64%`, `1.0x`) that bear no relationship to the `groupDailyPnl` or `sampleMembers` arrays. Compute them from the mock data so future data changes don't produce contradictions.
4. **Finances state lost on navigation** — All transactions live in component state with no localStorage persistence. Unlike settings (which persist to localStorage on save), leaving the Finances page and returning resets to the initial mock data. Add a localStorage read/write cycle or note this as a known limitation.
5. **Win Rate card orphaned in its own grid** — The group detail page places a single Win Rate card in a separate `grid sm:grid-cols-2 lg:grid-cols-3` row, producing a lone card on a full-width row. Merge it into the stats grid above (change it to a 4-column grid with 7 cards total, or fold Win Rate into the existing 6-card grid as a 7th item).

## Platform toggle inverts meaning of "Reconnect"

In `src/app/settings/page.tsx`, `handlePlatformToggle` unconditionally flips the status:

```typescript
const newStatus = p.status === "connected" ? "disconnected" : "connected";
```

The button label for a connected platform is "Reconnect", implying the platform stays connected (or drops and immediately reconnects). The current logic turns it off. The toast message reads the stale `platforms` state (pre-setState), so it says "reconnected" even though the platform just became disconnected — the toast is accidentally correct in phrasing but wrong in reality.

## Dead `useParams` in Account Detail

`src/app/accounts/[id]/page.tsx` imports `useParams` and calls `const params = useParams()`, but `params` is never referenced afterward. The page still renders `sampleAccount` regardless of the URL param. This mirrors the groups detail page (which *does* use `params.id` to set the group ID), suggesting it was intended for future account selection but left incomplete.

## Hardcoded group stats vs. mock data inconsistency

The group detail page displays:

- Total PnL: `$3,245.50` (literal)
- This Month's PnL summary box: also `$3,245.50`
- Actual sum of `groupDailyPnl` array: `$2,486.25`

These are already contradictory. The Trades Today (`12`), Win Rate (`64%`), and Avg Risk Multiplier (`1.0x`) have no backing data at all. Computing these from `groupDailyPnl.reduce(...)` and `sampleMembers` would cost a few lines and eliminate a class of future confusion.

## Finances page transience

The `FinancesPageContent` component initializes state from `initialTransactions` on every mount. Any added, edited, or deleted transaction disappears on navigation. The settings page already demonstrates the `localStorage.setItem` / `getItem` pattern for exactly this use case.
